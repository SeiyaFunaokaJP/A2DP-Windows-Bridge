## ウィンドウ

スタートメニューの **A2DP Windows Bridge**（または `a2dpwb.exe`）で起動します。左のメニューには次の画面があり（ホーム、コーデック、オーディオデバイス、アダプタ、診断、設定、このソフトについて）、ウィンドウの幅が狭いときはアイコンだけに畳まれます。ウィンドウは常駐の `a2dpwb-core.exe` の状態を表示しているだけなので、閉じても配信は止まりません（[トレイとフライアウト](#tray)を参照）。

### ホーム

- 保存したオーディオデバイスごとのカードが横に並びます: 状態、バッテリー、接続済みのものには使用中のコーデック（名前の代わりにリスト。下記を参照）とビットレート。選んだものとは別のコーデックで接続したときは、コーデックの行の名前の横に数秒間理由が出て（例: **aptX Adaptive（Opus 非対応）**。ほかに *使用中*、*は実験的*）、そのあとは警告の印だけが残ります（マウスを重ねると理由が出ます）。状態の行は **接続済み** とだけ表示します
- 各カードの下に **接続** / **切断**。接続できるデバイスは一度に 1 台です。別のデバイスで **接続** を押すと、使用中のものを切断してそのデバイスに接続します
- **音量**: ヘッドホンの音量（[音量](#volume)を参照）。スピーカーをクリックするとミュート、もう一度クリックするとミュート解除します。ほかのデバイスのカードにもスライダーが無効の状態で残ります
- 使用中のデバイスのコーデックは、そのカードのリストから選んですぐ切り替えられます（ゲーム用と音楽用など）: デバイスが対応するコーデック（[コーデック](#codecs) と同じ選択肢）が名前だけで並びます。**自動選択** の間も使用中のコーデックを表示し、コーデックを選ぶと自動選択はオフになります（オンに戻すのはコーデック画面で）。選ぶとすぐに反映されます（デバイスはそのコーデックで接続し直します。コーデック画面と同じく、次の選択は接続し直すまで待ちます）
- 使用中のデバイスの通信品質（小さなグラフ付き）をカードの下に表示します。出力ソースは **オーディオデバイス** で選びます。出力ソースに設定したアプリケーションがまだ起動していない間は、デバイスのカードにそう表示されます
- エラーには原因と、あればその直し方のボタン（**WinUSB ドライバに置き換える**、**ダウンロードページを開く**、**Bluetooth を再起動**、**もう一度試す**、**コーデック**、**オーディオデバイス** など）が付きます

サイドバーには、どの画面でも各デバイスについて同じ内容が表示されます。トレイのフライアウトには、使用中のデバイスについて表示されます。

### コーデック {#codecs}

保存したオーディオデバイスごとのコーデックを、デバイス 1 台につき 1 つのセクション（接続中は緑になる点、名前、**ペアリング済み** / **オーディオ** のタグ。アドレスは **オーディオデバイス** にあります）にコーデックのカードを並べて表示します。カードは、自分で並べ替えていなければ音質の高い順に並び、どれも 3 本のバー（音質・低遅延・安定性）と、デバイスが前回の接続で提示したかどうか（**対応** / **非対応**）が付きます。**対応しているコーデックのみ表示** がオン（既定）のときは、表示されるカードには **対応** のタグが不要なので付きません。

- **対応しているコーデックのみ表示**（既定でオン。オフにすると対応していないコーデックも表示します）: デバイスが提示しなかったコーデックを表示しません。デバイスを初めて接続する前は、すべて表示されます。カードの **対応** / **非対応** は印だけが緑 / 赤になります。実験的コーデックも含め、すべてのコーデックを使えます（実験的かどうかは README のコーデック表の 🧪 だけで示します）
- **対応するコーデックのうち最も音質の高いものを自動で選ぶ**（画面上部の、すべてのデバイス共通の設定。既定でオン）: 各デバイスが対応する最も音質の高いコーデックを、その最良の設定（高音質、コーデックが対応していれば 24 bit、デバイスが通知する最も高いサンプルレート。例: LDAC 96 kHz、LHDC V5 は最大 192 kHz。aptX Adaptive は 48 kHz で、[aptX Adaptive](#aptx-adaptive)を参照。Windows 側のレートはリサンプリングします）で使います。スイッチの下の説明のとおり、コーデックの選択・設定・順番を自分で決めるにはオフにします。カードは読み取り専用で既定の順番に並び、使用中（または自動で選ばれる）コーデックが強調表示されます。カードやその **...** をクリックすると、自動選択をオフにするか尋ねます（**自動選択をオフにする** / **キャンセル**）。オフにすると、デバイスごとにコーデックとその設定を選べます（まだ選んでいないデバイスは自動の選択のまま）。オンの間も、デバイスごとに選んだコーデックは保持されます。2.0.2 より前にいずれかのデバイスでコーデックを選んでいた場合は、オフで始まります
- 自動選択がオフのときは、カードをクリックするとそのデバイスのコーデックになり、すぐに保存されます。配信中のデバイスは、そのコーデックで接続し直します。デバイスが対応していないカード（**対応しているコーデックのみ表示** がオフのときに表示）をクリックすると、代わりにデバイスの順番で対応している最初のカードを選びます。順番を変えていなければ、対応する最も音質の高いコーデックです（[指定したコーデックがない場合](#codec-fallback)を参照）
- 自動選択がオフのときは、デバイスのカードをドラッグする（手の形はボタンを押している間だけ出ます。またはカード上で Alt＋矢印キーを押す）と、そのデバイスのコーデックの順番を好きなように並べ替えられます。順番はデバイスごとに保存され、**コーデックの順番をリセット** で元に戻ります（このボタンは、表示中のカードが既定の順番から外れている間だけ出ます。並べ戻せば既定の順番に戻ります）。まだコーデックを選んでいないデバイスは、この順番でデバイスが対応する最初のカードを使います。選んだコーデックにデバイスが対応していない場合も同じです（並べ替えていなければ、対応する最も音質の高いコーデック）。FastStream と Opus 05 は、どこに置いても選んだときだけ使います。自動選択がオンの間はこの順番を使いません。使用中のストリームのコーデックが変わる場合は接続し直します
- 配信中のデバイスで別のコーデックを選ぶと、そのコーデックで接続し直します。そのあとカード（とホームとトレイのフライアウトのコーデックのリスト）は接続し直すまで（**コーデックを切り替えています。少し待ってから次を選んでください。**、最短 1 秒、最長 15 秒）次の選択を待つので、続けて素早くクリックしても設定中の接続が途中で切れることはありません。コーデックの切り替えでは接続の通知は出ません（デバイスの接続では出ます）
- カードの **...** でそのコーデックの設定が開きます。**OK** でその設定のままコーデックを選びます。コーデックごとに設定を別々に覚えているので、別のコーデックを選んでから戻ると元の設定に戻ります。そのコーデックで使える項目のうち、デバイスが前回の接続で通知したものだけが出ます:
  - **音質**: LDAC は **高音質** / **中音質** / **低音質**（990 / 660 / 330 kbps）、LHDC V5 は **高音質** / **中高音質** / **中音質** / **低音質**（1000 / 900 / 500 / 400 kbps、Android の 4 段階）。aptX Adaptive は **高音質** / **低遅延**（[aptX Adaptive](#aptx-adaptive)を参照）。AAC、Opus、Opus 05、SBC、SBC XQ は **高音質** の 1 つだけで、選ぶのではなく表示だけです: デバイスが受け付ける最大のビットレート（ABR や VBR がある場合は、それで変動します。SBC と SBC XQ は、ビットプールとフレームの設定で決まるビットレートを表示します）。aptX、aptX HD、aptX LL、FastStream はコーデックでビットレートが決まっています。以前のバージョンで保存した、今はそのコーデックにない品質（aptX Adaptive の標準 / モバイル、AAC の低い段階など）は高音質として読み込みます
  - **ABR（適応ビットレート）**: LDAC、LHDC V5、aptX Adaptive、SBC、SBC XQ（[ABR](#abr)を参照）。AAC は **VBR**
  - **サンプルレート**: 自動は 48 kHz です（デバイスが 48 kHz を通知していなければ、通知した中で最良のレート）。96 kHz は遅延や相性の問題が増えるわりに聞き分けられる差がなく、Windows のミキサーも 48 kHz で動いているためです。96 kHz を使うにはここで選びます。デバイスが通知したレートだけを選べます（aptX Adaptive の 96 kHz は通知したデバイスだけ。[aptX Adaptive](#aptx-adaptive)を参照）
  - **ビット深度**: LDAC と LHDC V5 は 16 / 24 ビット（自動は 24 ビット。デバイスが通知したものだけ）、それ以外は 16 ビット
  - **ビットプール**（SBC、SBC XQ）: 最小と最大のビットプールを 2 つのつまみで決める 1 本のスライダーで、デバイスが通知した範囲（ダイアログに表示します）の中で動きます。最大が使うビットプールで、最小は使う中で最も低いもの（接続で設定する範囲の下限で、ABR が下げられる限度）です。**自動** で両方を戻します: 最大は音質に合わせ、最小はデバイスと ABR 自身のものになります。AAC と LHDC V5 のビットレートは、デバイスが通知した最大値を超えません

初期設定のままで一番良い音になります。ほとんどのデバイスは **自動** のままで足ります。LE Audio デバイス（実験的）のカードは LC3 の 1 枚と **ゲーミングヘッドセット向け低遅延（GMAP、実験的）** です（[LE Audio](#le-audio)を参照）。

内部では、A2DPWB はデバイスごとに 1 つの項目を `profiles.json` に持ち（コーデック、コーデックごとの設定、コーデックの順番）、そこでは「*デバイス* | *コーデック*」という名前です。ウィンドウとトレイのメニューにはデバイスの名前が表示されます。以前のバージョンでは 1 台のデバイスに複数のプロファイルを作れました。コーデック画面のあるバージョンで初めて起動すると、最後に使ったプロファイル（なければ最初のもの）を残して他をそこにまとめ、コーデックごとの設定（品質、サンプルレート、ビット深度、ABR、SBC の設定）はそのコーデックのものとして引き継ぎます。元のプロファイル名、出力ソース、パケットサイズは引き継がれません。元の `profiles.json` は、設定フォルダーに `profiles-before-codecs.json` として一度だけ保存されます。2.0.2 のプレリリースにあった **自動選択の順番…**（開発者モードの、すべてのデバイス共通の順番）は使われなくなり、今はデバイスごとに順番を持ちます。

### オーディオデバイス

A2DPWB が配信できるヘッドホンやスピーカーを、それぞれの設定とともに表示します。**デバイスを検索** で USB アダプターを使って近くのデバイスを探します（30 秒。応答した順に表示し、**停止** で終わります。ヘッドホンはペアリングモードに）。A2DPWB で以前ペアリングしたデバイスには **ペアリング済み** と付きます。検索で見つからないときは **手動入力:** にアドレスを入れて **使う** を押します。入力・貼り付けたアドレスはその場で整形されます（`aa-bb-cc-dd-ee-ff`、`AABBCCDDEEFF`、`AA BB CC DD EE FF` はどれも `AA:BB:CC:DD:EE:FF` になります）。保存したデバイスは名前の変更と削除ができ、次の設定があります:

- **出力ソース**: システムループバック（新しいデバイスの初期値）、仮想デバイス、アプリ（[キャプチャモード](#capture-modes)を参照）。横には、取り込むデバイスを Windows がミックスする形式（サンプルレートとビット深度。読み取り専用）が表示されます。デバイスのコーデック設定が別の形式を求めているときは琥珀色になり、下の行にその形式が出ます（変換して配信は続きます）。その下にはソースの説明が表示されます
- **Windows の既定の出力デバイスを自動切替**（仮想デバイスのとき）

一覧の上の **すべてのオーディオデバイス** には、すべてのデバイスに共通のスイッチがあります: **連動する Windows 音量**（[音量](#volume)を参照）、**オーディオデバイスのボタンで再生を操作**、**Bluetooth オーディオデバイスの最後の音量を記憶**。デバイスごとの **最大メディアパケットサイズ** は **開発者** 画面にあります（[最大メディアパケットサイズ](#max-packet)を参照）。

### 診断

- 配信中の **通信品質**: 実効ビットレート、パケット、送信前に破棄したパケット、音声取り込みの欠落、送信キュー、無線時間の使用率、電波の強さ（RSSI）、AFH のチャネル（[通信品質と AFH](#link-quality)を参照）
- 配信中の **コーデックの詳細**: メディアペイロード、ヘッダー、コーデックのフレームとパケットあたりのフレーム数、デバイスのエンドポイントが通知する内容と使用中のもの。SBC はビットプール、サンプルレート、チャネルモード、ブロック、サブバンド、ビット割り当て、AAC はオブジェクトタイプ、サンプルレート、チャネル、最大ビットレート、VBR、それ以外のコーデックはサンプルレート、ビット深度、最大ビットレート
- **接続フロー**: 直近の接続の 11 の段階（開始、Bluetooth アダプター、ACL / AVDTP 接続、コーデック能力の取得、コーデック選択、音声の取り込み、ストリーム設定、エンコーダー、ストリーム開始、音声送信、接続の維持と切断・再接続）を、かかった時間とともに OK / 警告 / 失敗で表示します。**フローをコピー** でコピーできます
- **ログ**: リアルタイムに表示し、レベル（すべてのレベル、情報以上、警告とエラー、エラーのみ）と文字列で絞り込めます。**表示中のログをコピー** で表示中の行をコピーします
- **HCI キャプチャを開始** / **HCI キャプチャを停止**（[送信ストリームの検証](#verify-stream)を参照）
- **診断情報をコピー**: バージョン・OS・アダプター・オーディオデバイス（コーデック、その設定と順番）・接続フロー・警告とエラー・直近のログをまとめてクリップボードへコピーします（不具合報告にそのまま貼れます）。**BT アドレスを伏せる**（既定でオン）で、アドレスは `<addr-1>`, `<addr-2>`...（アダプター自身は `<adapter>`）、デバイス名は `<device-1>`, `<device-2>`... に置き換わり、USB のシリアル番号、アプリのフォルダーより上のパス（`<path>\A2DPWB\logs\...`）、Windows のアカウント（ユーザー名と SID）も隠れます。不具合報告用にコピーするクラッシュレポートやエラーの文面にも同じ伏せ字が掛かります
- **問題を報告**:
  - **詳細ログ**: **詳細（debug）** または **すべて（trace、1 時間）** にすると、Bluetooth・USB・音声キャプチャ・エンコードについて大幅に多くのログを記録します。debug は 24 時間有効で再起動後も続き（起動時の問題用）、その後自動でオフになります。オンにして問題を再現し、診断パッケージを保存してください
  - **診断パッケージ > 保存…**: HCI キャプチャを含めるか（既定ではオフ。アドレスとデバイス名が残るので、求められた場合だけ）、テキストファイルの Bluetooth アドレスを伏せるかを選んでから、`.zip` を 1 つ保存します（設定フォルダーの `logs\bundles\`、新しい 3 件を保持）。中身は診断情報、コア・ウィンドウ・ドライバー補助のログファイル、クラッシュレポート、システム情報（USB Bluetooth アダプターとドライバー、Windows のペアリング済みデバイス、オーディオデバイス）、設定と各デバイスのコーデック設定（リンクキーは含みません）、HCI フライトレコーダーです。HCI キャプチャにはアドレスが残ります（ペアリングキーは含みません）。できるだけ GitHub の添付上限 25 MB に収まるようにしています（新しいログから最大 48 MB のテキスト、新しい 5 件の記録と 2 件のミニダンプ）
  - **GitHub で報告**（保存後）: バージョン・Windows ビルド・アダプター・ヘッドホン・コーデック・キャプチャ方式・診断情報（アドレスは伏せた状態）を入力済みの不具合報告を開き、診断パッケージをエクスプローラーで表示します。ファイルを報告にドラッグしてください

一度だけ起きた問題も調べられるよう、次のものは常に記録しています。

- **HCI フライトレコーダー**: 直近数分の Bluetooth 通信をメモリに保持し（メディアのペイロードは先頭のみ、ペアリングキーは除去）、ストリームが失敗したり接続が切れたりすると `logs\hci\` に保存します（新しい 10 ファイルを保持）
- **クラッシュレポート**: A2DPWB がクラッシュすると、`.dmp` ミニダンプと `.txt` を `logs\crash\` に保存します（プログラムごとに新しい 5 件を保持）

ディスク使用量には上限があります。通常の 1 日分のログは 1 MB 未満で、7 日分を保持します。詳細ログ中は 1 日のファイルにつき debug・trace の行は 100 MB まで（それ以降は翌日まで info 以上のみ）です。フライトレコーダーのファイルは最大でも数 MB で、10 件を保持します。

**設定 > 開発者モード** をオンにすると、**開発者** 画面に **対向受信テスト** のタブがあります（[対向受信テスト](#receiver)を参照）。

### アダプタ

- 検出した USB Bluetooth アダプターと、そのチップ、アドレス、USB ID、Bluetooth バージョン、**ドライバ**、**ファームウェア**。アダプターを抜き差しすると一覧は自動で更新されます。ドライバは **元のドライバ**（Windows かメーカーが入れたもの。マウスを重ねると名前が出ます）か **WinUSB ドライバ**（A2DPWB が使うもの）のどちらかです。Realtek のアダプターは、まだ使っていなくても USB のシリアル番号からアドレスを表示します。それ以外のアダプターのアドレスと Bluetooth バージョンは、Windows の Bluetooth か A2DPWB がそのアダプターを使うと表示されます（出ていない理由はマウスを重ねると出ます）。A2DPWB が使えないアダプター（MediaTek、Qualcomm）はドライバがそのままで、WinUSB とファームウェアのボタンは押せません
- **WinUSB ドライバに置き換える** / **元のドライバに戻す**（[セットアップ](setup#winusb)を参照）。毎回 Windows が管理者の許可を求めます
- ファームウェア用の **Bluetooth チップ** と、**ファームウェアをダウンロード**、**ダウンロードページを開く**、**設定フォルダを開く**（[ファームウェア](setup#firmware)を参照）
- **AFH**: 自動、オフ、手動。横に Wi-Fi のチャネルが表示されます: 自動では今避けているチャネル、オフでは何も表示されず（どちらも読み取り専用）、手動では入力したチャネル（[通信品質と AFH](#link-quality)を参照）
- **Bluetooth スタック**: 停止中（最初の検索か接続で起動）、起動中、準備完了、エラーの表示と **Bluetooth を再起動**

### 設定

| 項目 | 設定 |
|:-----|:-----|
| 表示 | 言語、テーマ（システム / ライト / ダーク） |
| 起動 | **Windows 起動時に開始** と **トレイに入れた状態で起動**（[Windows 起動時に開始](#autostart)を参照）、**システムトレイに最小化** と **トレイアイコンのクリックでメインウィンドウを開く**（[トレイとフライアウト](#tray)を参照） |
| 通知 | **デバイスの接続時に通知する**（デバイス、バッテリー、コーデックとその設定。既定でオン）、**バッテリー残量が少ないときに通知**: **20% 未満**（既定）、**10% 未満**、**5% 未満**、**通知しない**。1 回の接続につき 1 回だけです（バッテリーが 5 ポイント上まで戻ってから、また通知します） |
| 更新 | **アップデートを確認**、**起動時にアップデートを確認**、**アップデート確認にプレリリースを含める**（ベータ版も通知）、**今すぐ更新**（[更新](#updates)を参照） |
| 詳細 | **開発者モード**（コーデックの上書き設定、デバイスごとの **最大メディアパケットサイズ**、ログの設定、対向受信テストがある **開発者** 画面を追加し、ログを詳しくします。再起動は不要）、**設定フォルダ** と **設定フォルダを開く**、**セットアップを実行** |
| A2DP Windows Bridge について | バージョン、ライセンス、サードパーティライセンス、**A2DP Windows Bridge を終了** |

### 初回セットアップ

初回の起動（オーディオデバイスがまだないか、WinUSB のアダプターがない）では **A2DP Windows Bridge のセットアップ** が開きます: アダプタを選ぶ、ドライバとファームウェア、オーディオ機器を探す（「接続」でデバイスを最良の設定で保存して接続。この手順には **Windows 起動時に開始** と **トレイに入れた状態で起動** もあります）。[セットアップ](setup#first-run)を参照してください。**設定 > セットアップを実行** でもう一度開けます。

## トレイとフライアウト {#tray}

A2DPWB はウィンドウの有無にかかわらず、システムトレイで動き続けます。

- トレイのアイコンを **左クリック** するとフライアウトが開きます: デバイスと状態、**接続** / **切断**、音量、デバイスの切り替え、コーデック（ホームと同じくリストで選べます）、通信品質、**アプリを開く**。高さは表示する内容にちょうど合わせます。Esc かほかの場所のクリックで隠れます。エラーの直し方がメインウィンドウの画面（コーデック、オーディオデバイス、アダプタ）にある場合は、ボタンでウィンドウのその画面を開きます。**設定 > トレイアイコンのクリックでメインウィンドウを開く** がオン（既定はオフ）のときは、左クリックでフライアウトの代わりにメインウィンドウが開きます
- **右クリック** でメニューが開きます: **A2DP Windows Bridge を開く**、最初の 10 台のデバイス（名前で表示。LE Audio の項目には「(LE Audio)」が付きます。配信中のものにチェック。クリックするとそのデバイスに接続）、**切断**、**終了**。メニューはウィンドウを起動せずにすぐ開きます
- アイコンのツールチップで待機中か接続済みかが分かります

**設定 > システムトレイに最小化** がオン（既定）のときは、ウィンドウを最小化しても閉じてもトレイに隠れるだけで、配信は続きます。オフのときは、最小化するとタスクバーに入り、ウィンドウを閉じると A2DPWB が終了します。トレイのメニューの **終了** か **設定 > A2DP Windows Bridge を終了** で、配信を止めてアダプターを放し、A2DPWB を完全に終了します。

## Windows 起動時に開始 {#autostart}

**設定 > Windows 起動時に開始** をオンにすると、サインイン時に A2DPWB が起動します。**トレイに入れた状態で起動** がオンならバックグラウンドで起動し、出るのはトレイのアイコンだけで、ウィンドウはそこから開きます。オフ（既定）ならメインウィンドウが開きます。中身は `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` の値 `A2DPWB`（データは `"<フォルダー>\a2dpwb-core.exe"`。**トレイに入れた状態で起動** がオンなら後ろに `--background` が付きます）です。手動で無効にするには、この値を削除してください。v1 に v2 を上書きでインストールすると、**トレイに入れた状態で起動** はオンになります（v1 は常にトレイに入れた状態で起動していたため）。

## CLI モード

`a2dpwb-core.exe --cli` で、ウィンドウと同じコアを使ってコンソールから配信します。先に A2DPWB を終了してください（トレイ > **終了**）。アダプターを使えるのは一度に 1 つのプログラムだけです。CLI は保存したデバイスの設定を読みません。すべてオプションで指定します。

### 基本

```bash
# 最適なコーデックを自動選択
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF
```

Ctrl+C で配信を止めます。CLI は状態、コーデックとビットレートを表示し、最後に送信したパケット数と破棄したパケット数を表示します。

### コーデック選択

```bash
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c ldac      # LDAC
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c aptxhd    # aptX HD
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c aptxll    # aptX Low Latency
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c aptx      # aptX
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c aac       # AAC
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c sbc       # SBC
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c lhdcv5    # LHDC V5
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c opus      # Opus（試験的。48 kHz、256 kbps）
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c opus05    # PipeWire の Opus 05（試験的。相手が PipeWire のとき）
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c aptxad    # aptX Adaptive（48 kHz。96 kHz は --rate 96000）
```

自動選択の優先順位: LHDC V5 > LDAC > aptX Adaptive > Opus（試験的） > aptX HD > aptX > aptX LL > AAC > SBC XQ > SBC（FastStream、Opus 05 はいずれも試験的で、明示的に選んだときだけ）

指定したコーデックをヘッドホンが提供していない場合、CLI は理由を表示してエラーで止まります。ヘッドホンが提供する一番良いコーデックを使うには `-c auto`（既定）にするか、`--fallback` を付けると、アプリと同じく指定したコーデックの代わりに提供されている最良のコーデックを使います -- [aptX ファミリーと aptX Adaptive](#aptx-compatibility)を参照してください。`--no-experimental` を付けると実験的コーデック（aptX HD、aptX LL、Opus、Opus 05、FastStream）を使いません。アプリでは常に使います。

### 品質

```bash
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c ldac -q hq   # 高音質 990 kbps（既定）
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c ldac -q sq   # 中音質 660 kbps
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c ldac -q mq   # 低音質 330 kbps

# LHDC V5: hq 1000 / mhq 900 / sq 500 / mq 400 kbps
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c lhdcv5 -q sq   # 中音質 500 kbps

# aptX Adaptive: hq 427 / ll 265 kbps
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c aptxad -q ll   # 低遅延
```

ほかのコーデックには品質の選択がなく、`hq`（ヘッドホンが受け付ける最大のビットレート。aptX、aptX HD、aptX LL、FastStream はコーデックで固定）で動きます。そのコーデックにない段階（LHDC V5 以外の `mhq`、aptX Adaptive の `sq` / `mq`、aptX Adaptive 以外の `ll`）は `hq` として扱います。

### ABR（アダプティブビットレート） {#abr}

```bash
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c ldac -a
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c lhdcv5 -a
a2dpwb-core.exe --cli -d AA:BB:CC:DD:EE:FF -c aptxad -a
```

ABR は Bluetooth 接続が不安定な場合にビットレートを自動的に下げ、安定すると引き上げます。LDAC は品質モード間を移動し、LHDC V5 は Android と同じ方針で 160〜400 kbps の範囲で動き、aptX Adaptive は高音質のとき段階を移動します（[aptX Adaptive](#aptx-adaptive)を参照）。ウィンドウでは、コーデックの設定（**コーデック** 画面のカードの **...**）にあります。

### デバイス検出

```bash
# USB アダプターで近くのデバイスを探す（10 秒。長くするには --scan 20 など）
a2dpwb-core.exe --cli --scan
```

先にヘッドホンをペアリングモードにしてください。

### オプション一覧 {#all-options}

| オプション | 説明 |
|:-----------|:-----|
| `-d <addr>` | ヘッドホン / 受信機の Bluetooth アドレス（`AA:BB:CC:DD:EE:FF`） |
| `-c <codec>` | `ldac`、`aptxhd`、`aptxll`、`aptx`、`aac`、`sbc`、`lhdcv5`、`opus`、`opus05`、`aptxad`、`auto`（既定: `auto`） |
| `-q <mode>` | 品質: `hq`（高音質、既定）。LDAC と LHDC V5 は `sq`（中音質）と `mq`（低音質）も可。aptX Adaptive は `ll`（低遅延）も可。ほかのコーデックはどの段階も `hq` として扱う |
| `-a` | ABR（LDAC、LHDC V5、aptX Adaptive。SBC / SBC XQ はビットプールの適応） |
| `--fallback` | `-c` のコーデックをヘッドホンが提供していなければ、エラーにせずアプリと同じく提供されている最良のコーデックを使う |
| `--no-experimental` | 実験的コーデック（aptX HD、aptX LL、Opus、Opus 05、FastStream）を使わない（アプリでは常に使います） |
| `-m <mode>` | キャプチャモード: `loopback`（既定）、`virtual`、`app` |
| `--audio-device <id>` | `-m virtual` で使う再生デバイス |
| `--app <exe>` | `-m app` で使う実行ファイル（例: `spotify.exe`） |
| `--rate <hz>` | 取り込みのサンプルレート（既定: デバイスのレート） |
| `--bits <16\|24>` | ビット深度（既定: コーデックが対応していれば 24） |
| `--max-packet <バイト数>` | 最大メディアパケットサイズ、679〜1679、既定 1023（[最大メディアパケットサイズ](#max-packet)を参照） |
| `--afh <auto\|off\|6,11>` | AFH ホストチャネル分類（[通信品質と AFH](#link-quality)を参照） |
| `--remote-sink <host[:port]\|auto>` | 対向受信機が受け取った内容を表示。`-d` がなければその受信機へ送信（[対向受信テスト](#receiver)を参照） |
| `--scan [秒]` | 近くのデバイスを表示して終了（既定 10 秒） |
| `-h` | ヘルプを表示 |

開発・テスト用に `--hci-tcp <host:port>`（WinUSB アダプターの代わりに TCP 経由の仮想コントローラー）、`--test-tone`（キャプチャ音声の代わりに左 1 kHz / 右 1.5 kHz）、`--duration <秒>`（指定秒数で停止）、`--hci-capture <file.pklg>`（実行全体の HCI キャプチャ）もあります。[ビルド](../building#emu)を参照してください。

`--cli` を付けない `a2dpwb-core.exe` は常駐のプログラムで、ウィンドウも起動します。`--background` を付けるとトレイのアイコンだけで起動します（**トレイに入れた状態で起動** がオンのとき **Windows 起動時に開始** が使います）。`a2dpwb-core.exe --quit` は、動いている A2DPWB に配信を止めて終了するよう頼みます（インストーラーが使います）。

## キャプチャモード {#capture-modes}

A2DPWB は 3 つのオーディオキャプチャモードに対応しています。モードによって、音声経路のどこを取り込むかが違います:

| モード | 取り込むもの |
|:-------|:-------------|
| システムループバック | Windows の既定の出力デバイスで再生される音（全アプリのミックス） |
| 仮想デバイス | 選んだデバイス（VB-CABLE 等）にアプリが出力した音 |
| アプリ | 1 つのアプリ（とその子プロセス）が再生する音だけを、アプリ自身の処理の後で取り込む。Windows 11 または Windows 10 バージョン 2004（ビルド 19041）以降が必要 |

**オーディオデバイス** 画面でも、**出力ソース**の下に同じ説明が表示されます。新しいデバイスはシステムループバックで取り込み、ほかに何もインストールしなくても使えます。仮想デバイスやアプリにするときは、そこで選んでください。

システムループバックは音声をコピーするだけで、既定の出力デバイスから音声を奪いません。音声は Bluetooth ヘッドホンに加えて、そのデバイス（スピーカー、HDMI 接続のテレビなど）からも出続けます。ヘッドホンだけで聞くには、VB-CABLE などどこからも音が出ないデバイスを使って、仮想デバイスモードにしてください。

仮想デバイスモードで **既定デバイスを自動切替** をオンにすると、ストリーミング中は選択したデバイスが Windows の既定の出力になります。Windows の設定を変えなくても、アプリの音声がそのデバイスに出力されます。ストリーミングを止めると、元の既定デバイスに戻します。

- **オーディオデバイス**の一覧には、A2DPWB が仮想オーディオデバイスと判定したデバイスだけが表示されます。1 つもなければ、**オーディオデバイス**画面に **VB-Cableをダウンロード** が出ます。
- 既定の通信デバイス（通話アプリが使うもの）は変更しません。
- アプリによっては、再起動するまで元のデバイスで再生し続けます。
- A2DPWB が異常終了した場合、既定デバイスは元に戻りません。Windows のサウンド設定で変更してください。

### アプリモード {#application-mode}

アプリモードは、1 つのアプリ（音楽プレーヤー、ブラウザー、エフェクトアプリなど）の音声を送ります。**アプリ**の一覧から選んでください。一覧には現在音声を再生しているアプリが表示されます。見つからない場合は、そのアプリで再生を始めてから **更新** を押してください。子プロセスも含むので、別プロセスで音声を再生するブラウザーでも使えます。

- アプリが起動していなくても接続できます。A2DPWB はヘッドホンに接続し、アプリが起動すると送信を始めます。ストリーミング中にアプリを終了しても接続は保たれ、アプリを起動し直すと自動で再び取り込みます。
- アプリ自身の出力先デバイスからも音は出続けます。ヘッドホンだけで聞くには、その出力先デバイス（マスター音量）をミュートしてください。A2DPWB が取り込む音には影響しません。ただし、Windows の音量ミキサーでアプリ自体をミュートすると、ヘッドホンも無音になります。
- Windows の音量ミキサーにあるそのアプリのスライダーで、ヘッドホンに送る音量が変わります（出力先デバイスの音量も一緒に変わります）。マスター音量や音量キーでは送る音は変わりません。**連動する Windows 音量** がオンなら、代わりにヘッドホンの音量が変わります（[音量](#volume) を参照）。
- Windows が A2DPWB の指定したサンプルレートに変換するので、サウンド設定のデバイス形式に左右されません。
- Windows 10 バージョン 2004（ビルド 19041）より前には、アプリ単位のキャプチャがありません。その PC でアプリモードのキャプチャに設定したデバイスで接続すると、別の出力ソースを選ぶよう求めるエラーになります。

### 音量 {#volume}

ストリーミング中、ヘッドホンが AVRCP 絶対音量に対応していれば、ホームとトレイのフライアウトに **音量** スライダーが表示されます。ヘッドホン側の音量を変えるので、送る音声のビット数は削られません。横のスピーカーでミュート（ヘッドホンの音量を 0 に）とミュート解除（元の音量に戻す）ができます。ヘッドホンの音量ボタンやタッチ操作で変えた値もスライダーに反映されます。

**連動する Windows 音量**（**オーディオデバイス** で全デバイス共通。初期状態でオン）で、ストリーミング中に Windows の音量とヘッドホンの音量を一つの音量として連動させます。連動するのは A2DPWB が取り込むデバイスの Windows の音量で、システムループバックとアプリモードでは既定の出力デバイス、仮想デバイスモードでは選んだデバイスです。オフにすると、Windows の音量とヘッドホンの音量は別々になります。

- ヘッドホンの音量ボタンやジェスチャー、**音量** スライダーで変えると連動先の Windows の音量が変わり、サウンド設定でそのデバイスのスライダーを動かすとヘッドホンの音量が変わります。
- 音量キーと Windows の音量フライアウトは常に既定の出力デバイスに働くので、ヘッドホンの音量が変わるのは連動先が既定の出力デバイスのときだけです（基本的に常にそうなります。仮想デバイスモードで **既定デバイスを自動切替** がオフの場合を除く）。
- ストリーミング開始時は Windows の音量をヘッドホンの音量に合わせ、終了すると元の音量に戻します。
- 音声は Windows の音量がかかる前に取り込むので、音量を下げるのはヘッドホン側の 1 回だけです。連動先の音量で取り込む音も変わる場合は音量が二重にかかるので、連動をオフにしてください（[システム全体のエフェクトアプリ](#effects-apps) を参照）。
- ミュートは連動しません。出力デバイスをミュートして PC から音を出さないようにしても、ヘッドホンはミュートされません。

以前のバージョンでは、デバイスが別の出力デバイスの音量に連動するよう選べました（開発者モード）。この選択は使われなくなりました。

**Bluetooth オーディオデバイスの最後の音量を記憶**（**オーディオデバイス** で全デバイス共通。初期状態でオン）は、オーディオ機器ごとに自身の音量を保存し、接続したらすぐ、音声を送る前に設定し直します。ある機器の音量が別の機器に引き継がれることはありません。オフにすると、各機器は自身が最後に使っていた音量で始まり、前回 A2DPWB で使った音量よりずっと大きいことがあります（スマートフォンで使った後など）。

### ヘッドホンのボタン {#headphone-buttons}

ストリーミング中は、ヘッドホンの再生/一時停止・曲送り・曲戻しの操作（ボタンやタッチ操作。WH-1000XM4 のダブルタップなど）で PC の再生を操作できます。A2DPWB はこれを Windows のメディアキーとして渡し、Windows のメディアコントロールに表示されているアプリ（Spotify、ブラウザー、メディアプレーヤーなど）が受け取ります。停止も渡します。

- 再生と一時停止はどちらも Windows の再生/一時停止キーとして扱うので、ヘッドホン側の再生状態の認識がずれていても、タップのたびに再生と一時停止が切り替わります。
- A2DPWB は再生中かどうか（キャプチャする音声があるかどうか）をヘッドホンに伝えるので、外すと一時停止するヘッドホンも正しい操作を送れます。
- 早送り・巻き戻し（ボタンの長押し）は Windows に対応するメディアキーがないため無視します。
- 音量の操作はヘッドホン自体の音量を変えます。**連動する Windows 音量** で連動先の Windows の音量も変わります（[音量](#volume) を参照）。
- **オーディオデバイス > オーディオデバイスのボタンで再生を操作** でデバイスごとにオフにできます（別のプログラムもメディアキーに反応して二重に動く場合など）。

ヘッドホンが AVRCP に対応している必要があります（ほぼすべてのヘッドホンが対応しています）。対応していない場合も、ボタンが使えないだけでストリーミングは通常どおり動作します。

### システム全体のエフェクトアプリ {#effects-apps}

システム全体にかかるエフェクトアプリ（イコライザー、音質補正、バーチャルサラウンドなど）の多くは、自分の仮想出力デバイスを追加します。他のアプリはそのデバイスに音を再生し、エフェクトアプリは処理した音を、エフェクトアプリで選んだ出力先デバイスに再生します。A2DPWB でどのモードを選ぶかで、エフェクトがかかった音になるかが決まります:

| 設定 | ヘッドホンに届く音 |
|:-----|:-------------------|
| 仮想デバイス: エフェクトアプリ自身の仮想デバイス | エフェクト**前**の音（アプリがエフェクトアプリに渡す音） |
| アプリ: エフェクトアプリ | エフェクト**後**の音（エフェクトアプリが再生する音。おすすめ） |
| 仮想デバイス: エフェクトアプリの出力先デバイス（出力先を VB-CABLE にした場合など） | エフェクト後の音（アプリモードが使えない Windows 向け） |

アプリモードでは、エフェクトアプリの出力先はどのデバイスでも構いません。A2DPWB が取り込むのはアプリが再生する音で、デバイスが鳴らす音ではないので、出力先は音の行き先として置いておくだけです。PC でも同時に鳴らないように、誰も聞いていない出力（モニターの HDMI 音声など）を選ぶか、そのデバイスのマスター音量をミュートしてください。VB-CABLE などの仮想デバイスを音の捨て場にしてもよいですが、必須ではありません。出力先のデバイスは有効で、接続されている必要があります。

エフェクトアプリ自身の仮想デバイスが Windows の既定の出力デバイスの場合、その音量はエフェクトアプリが受け取る音も下げます。**連動する Windows 音量** がオンだと、音量の変更が二重に（エフェクトアプリの入力とヘッドホンの両方に）かかります。これをオフにして、ヘッドホンの音量か **音量** スライダーを使ってください。

#### A2DPWB が自分の仮想出力デバイスを持たない理由 {#no-virtual-device}

Windows の出力デバイス一覧に Bluetooth ヘッドホンを出し、エフェクトアプリから直接選べるようにするには、カーネルモードのオーディオドライバーが必要です。A2DPWB はこれを含めていません:

- カーネルのオーディオドライバーを作って保守するのは大がかりな作業で、不具合があると Windows ごと停止（ブルースクリーン）します。
- Windows 10 / 11 は Microsoft の署名があるドライバーしか読み込みません。署名を受けるには EV コード署名証明書（年に数百米ドル）と Microsoft Partner Center のアカウントが必要で、通常は法人として登録します。
- 署名を回避する方法は Windows のテスト署名モードだけですが、システムのセキュリティが下がり、一部のソフト（アンチチートのあるゲームなど）が動かなくなります。A2DPWB はこの方法を使いません。

同じ用途には、アプリモードか、無料の仮想デバイス（VB-CABLE など）を使ってください。

- 既定デバイスを変更する公開 API は Windows にないため、他の音声切り替えツールと同じく非公開の IPolicyConfig インターフェースを使います（Windows 10 / 11）。

{: .warning }
システムループバックと仮想デバイスは WASAPI 共有モードを使用します。サンプルレートが自動のとき（自動選択も）は、A2DPWB が 48 kHz（ヘッドホンが 48 kHz を通知していなければ、通知した中で最良のレート）を要求し、デバイスの「既定の形式」から WASAPI がそのレートにリサンプリングします。LDAC の 96 kHz を利用するには、コーデックの設定で 96 kHz を選んでください。**サウンド設定 → デバイスのプロパティ → 詳細 → 既定の形式** を変える必要はありません。

## コーデック比較

| コーデック | 最適な用途 | トレードオフ |
|:-----------|:-----------|:-------------|
| LDAC (HQ) | 最高音質 | レイテンシーが高い、安定した接続が必要 |
| LDAC (ABR) | 音質 + 安定性 | 接続状況に応じてビットレートが変動 |
| aptX HD | 高音質、幅広いデバイス対応 | 固定 576 kbps |
| aptX | aptX 対応機器が最も多い | 16-bit、352/384 kbps |
| aptX LL | ゲーム、動画（低レイテンシー） | 音質が低い (16-bit) |
| AAC | Apple デバイス、良い効率 | 中程度の音質 |
| SBC | 最大の互換性 | 最低の音質 |

**コーデック** 画面では、同じ比較を各コーデックのカードの 3 本のバーで表示します。

## aptX ファミリーと aptX Adaptive {#aptx-compatibility}

A2DPWB は [libopenaptx](https://github.com/pali/libopenaptx) でエンコードする 3 種類の aptX コーデックと、[AKS-Logic/aptx-adaptive-linux](https://github.com/AKS-Logic/aptx-adaptive-linux) のエンコーダーでエンコードする aptX Adaptive に対応しています。

{: .warning }
**aptX HD・aptX Low Latency は実験的な対応です。** Android / PipeWire の実装に合わせ、エンコード→デコードの往復テストは通っていますが、実機のヘッドホンでの検証はまだです。

{: .note }
**クラシック aptX だけが目的なら**、Windows 10 標準の Bluetooth スタックがクラシック aptX に対応しています（aptX HD・aptX LL・aptX Adaptive は非対応）。その場合 A2DPWB は不要です。A2DPWB が主に役立つのは LDAC・aptX HD・aptX Low Latency です。

| コーデック | Vendor ID / Codec ID | RTP ヘッダー | 対応状況 |
|:-----------|:---------------------|:-------------|:---------|
| aptX Adaptive | 0x000000D7 / 0x00AD | あり | 対応（265-427 kbps、48 / 96 kHz、24-bit） |
| aptX HD | 0x000000D7 / 0x0024 | あり | 対応（576 kbps、24-bit 入力） |
| aptX | 0x0000004F / 0x0001 | なし | 対応（44.1/48 kHz で 352/384 kbps） |
| aptX Low Latency | 0x0000000A または 0x000000D7 / 0x0002 | なし | 対応（352 kbps） |

### aptX Adaptive {#aptx-adaptive}

{: .note }
**aptX Adaptive は 48 kHz で実際のヘッドホンでの動作を確認済みです。** 2.0.2-beta.6 で EarFun Air Pro 4+ に送り、途切れも音飛びもなく、クラシック aptX と同じくらい安定していたと報告がありました（[#86](https://github.com/SeiyaFunaokaJP/A2DP-Windows-Bridge/issues/86)）。また、単体テスト、上流のビット単位で一致するテスト一式、仮想 Bluetooth シンク（`tools/emu`。RTP ヘッダー、パケットの大きさ、フレームの種類を確かめます。公開されたデコーダーがないため音声は復号しません）とのエンドツーエンドテストには合格しています。上流は Linux / PipeWire で Bose QuietComfort Ultra（第 1 世代）と B&W Px7 S2e での 48 kHz・高音質と低遅延の動作を報告しています。96 kHz（高音質 646 kbps）も実際のヘッドホンで動作を確認しました（[#86](https://github.com/SeiyaFunaokaJP/A2DP-Windows-Bridge/issues/86)）。コーデックの設定で 96 kHz を選んだとき（CLI は `--rate 96000`）、ヘッドホンがそれを通知する R2 のシンクなら使います（設定で選べるのもそのときだけです）。低遅延では使いません。自動（自動選択も）は 48 kHz です。[報告を歓迎します](https://github.com/SeiyaFunaokaJP/A2DP-Windows-Bridge/issues/11)。

エンコーダーは [AKS-Logic/aptx-adaptive-linux](https://github.com/AKS-Logic/aptx-adaptive-linux) の Rust だけで書かれた aptX Adaptive エンコーダー（MIT）です。上流はこれをクリーンルームでの再実装とし、数値テーブルは合法に入手した Qualcomm の出荷済みバイナリと無線のキャプチャから再構成したと説明しています。Qualcomm のコード、SDK、バイナリは含みません（[ライセンス](../licenses)を参照）。

- **選び方**: ヘッドホンが LHDC V5 も LDAC も提供していなければ、自動選択で選ばれます。**コーデック** 画面で **aptX Adaptive** を選ぶか、`-c aptxad` を指定することもできます。
- **形式**: 48 kHz ステレオ、24 bit。96 kHz を選べば、96 kHz を通知するデバイス（aptX Adaptive R2）には高音質で 96 kHz。44.1 kHz を指定しても 48 kHz で取り込みます。
- **ヘッドホン**: R1 のシンク（能力の拡張がないもの。例: B&W Px7 S2e）と R2 のシンク（R2 のビットストリーム）。

| 品質（**...** / `-q`） | R1 のシンク | R2 のシンク | パケット |
|:----------------------------|:------------|:------------|:---------|
| 高音質（`hq`） | 427 kbps | 427 kbps | 12 ms、656 バイト |
| 低遅延（`ll`） | 265 kbps | 270 kbps | 10 ms、348 バイト |

`ll` を使うのは aptX Adaptive だけです。ほかのコーデックでは高音質として扱います。

**ABR**（コーデック設定の **ABR**、CLI の `-a`）: 高音質のとき、送信キューに 3 パケット以上ある間はビットレートを 1 段下げ（標準、モバイルの順で、それより下げません。最短でも約 0.5 秒おき）、約 3 秒間キューが 1 パケット以下なら 1 段上げます（高音質まで）。標準とモバイル（R1 は 364 / 318 kbps、R2 は 270 / 204 kbps）は品質としては選べなくなりました。それで保存したデバイスや `-q sq` / `-q mq` は高音質で動きます。低遅延には ABR はありません。

### aptX Adaptive から aptX への「フォールバック」ではありません

接続時、ヘッドホンは対応コーデックの**一覧**（AVDTP ストリームエンドポイント）を通知し、A2DPWB はその中から 1 つを選びます。aptX Adaptive とクラシック aptX は一覧の中の別々の項目なので、コーデックの中で一方からもう一方へ「フォールバック」するわけではありません。

- **ヘッドホンがクラシック aptX も通知している場合** -- Qualcomm は aptX Adaptive を aptX / aptX HD と下位互換があると案内しているため、多くの aptX Adaptive 対応ヘッドホンがこれに該当します。Auto は aptX Adaptive を選びます（aptX HD・aptX より上位）。クラシック aptX は選んだときに使われ、ヘッドホンの一覧にある独立したコーデックであって、aptX Adaptive の縮退モードではありません。
- **ヘッドホンが aptX Adaptive のみを通知している場合**（クラシック aptX・aptX HD・aptX LL がない） -- aptX を選ぶと、ヘッドホンが提供する最良のコーデック（**コーデック** 画面のデバイスの順番で最初のもの。通常は aptX Adaptive）にフォールバックします。

自動選択の優先順位: LHDC V5 > LDAC > aptX Adaptive > Opus（試験的） > aptX HD > aptX > aptX LL > AAC > SBC XQ > SBC（FastStream、Opus 05 はいずれも試験的で、明示的に選んだときだけ）

### 指定したコーデックがない場合 {#codec-fallback}

ヘッドホンが通知していないコーデックを明示的に指定した場合の動作です。

| 場所 | 動作 |
|:-----|:-----|
| アプリ（**コーデック**、自動選択オフ） | デバイスの順番（カードを並べ替えていなければ自動選択の優先順位）で、ヘッドホンが提供する最初のコーデックで、自動選択と同じように接続します（Opus を選び、ヘッドホンが aptX Adaptive・aptX・AAC・SBC を提供する場合は、Opus の下の aptX ではなく aptX Adaptive。SBC XQ を先頭に並べていれば SBC XQ）。代わりに使ったコーデックとその理由はコーデックの行に数秒間表示します。ヘッドホンが提供していないコーデックを試すことはありません。**コーデック** 画面では、前回の接続でヘッドホンが提供しなかったカードを押すと代わりにそのコーデックを選び、以前選んだコーデックをヘッドホンが提供しない場合は、使われるコーデックを選んだものとして表示します。 |
| CLI（`-c <codec>`） | エラー（「デバイスは ... に対応していません」）で止まります。aptX・aptX HD・aptX LL を指定し、ヘッドホンが aptX Adaptive しか提供していない場合は、その旨を表示します。アプリと同じように切り替えるには `--fallback` を付けるか、`-c auto` にしてください。 |

以前のバージョンには **このコーデックが使えない場合は、対応している別のコーデックを使う** というオプションがありましたが、今は常にこの切り替えを行います。2.0.2 の一部のプレリリースは、最良のものではなく、選んだコーデックの次に低いコーデックを使っていました。

このオプションは **コーデック** 画面の上部にあり、すべてのデバイスに適用されます（Auto では使いません）。

### ヘッドホンが別の機器とも接続中でコーデックが出てこない {#sep-in-use}

ヘッドホンはコーデックごとにストリームエンドポイント（SEP）を提供します。デュアル（マルチポイント）接続でスマホや PC へ再生中のエンドポイントは **使用中** と通知され、その再生が止まるまでそのコーデックは使えません。また、接続が 1 台のときだけハイレゾコーデック（LDAC・L2HC など）を提供するヘッドホンもあります。この場合 A2DPWB はログに次のように記録します。

```
remote SEP 6: sink audio, IN USE (codec not queried)
remote SEPs in use by another connection: 1 of 6 audio sink SEP(s); ...
capability discovery complete (LDAC=false ... , 1 of 6 audio sink SEP(s) in use)
```

エラーも「別の機器が使用中」と表示します。スマホや PC との接続を切る（またはヘッドホンのアプリでデュアル接続をオフにする）と、もう一度接続してください。PC 内蔵の Bluetooth がヘッドホンとペアリングされたままの場合も「別の機器」にあたります。

### サンプルレート

aptX・aptX HD・aptX LL が対応するのは 44.1 kHz と 48 kHz のみです（aptX Adaptive は 48 kHz。96 kHz を選び、ヘッドホンが通知していれば 96 kHz）。A2DPWB はヘッドホンが通知したサンプルレートから 1 つを選び（自動のときは 48 kHz、なければ 44.1 kHz）、WASAPI にリサンプリングさせます。aptX のために Windows のサウンド設定を変更する必要はありません。

### ヘッドホンが提供するコーデックの確認方法

1. ヘッドホンに接続します。
2. **診断** を開き、ログの絞り込みに `remote` と入力します。

同じ行は設定フォルダーのログファイル（`%APPDATA%\A2DPWB\logs\a2dpwb-core.<日付>.log`）にもあり、CLI モードではコンソールに表示されます。以下の行で、ヘッドホンが通知しているコーデックを正確に確認できます。

```
remote supports aptX (SEID ..., [...])
remote supports aptX Adaptive (SEID ..., [...])
remote vendor codec 0x........./0x.... (SEID ...) - unsupported
capability discovery complete (LDAC=false aptX HD=false aptX LL=false aptX=true aptX Adaptive=true SBC=true SBC XQ=true AAC=true LHDC V5=false Opus=false Opus 05=false FastStream=false)
```

- `aptX=true` -- クラシック aptX を使用できます（`aptX Adaptive=true` であっても同様）。Auto はこちらを使います。
- `aptX=false`・`aptX HD=false`・`aptX LL=false` かつ `aptX Adaptive=true` -- ヘッドホンは aptX Adaptive しか提供していません。aptX Adaptive を選ぶか、Auto・AAC・SBC を使ってください。
- `aptX Adaptive=true [not usable]` -- ヘッドホンの aptX Adaptive に、A2DPWB が必要とする 48 kHz ステレオがありません。
- `remote vendor codec ... - unsupported` -- A2DPWB が実装していないその他のベンダーコーデックです。

## 最大メディアパケットサイズ（デバイスごと） {#max-packet}

各デバイスの **最大メディアパケットサイズ**（**開発者** 画面に保存済みデバイスごとの欄があります。CLI では `--max-packet <バイト数>`）で、Bluetooth パケット 1 つに入れる音声データの上限を 679〜1679 バイトの範囲で設定できます。オーディオ機器ごとに別の値を使えます。開発者画面は開発者モード（**設定 > 開発者モード**）のときに表示されます。ほとんどの人は使う必要がありません。オーディオ機器側の上限（MTU）も常に適用され、A2DPWB は小さい方を使います。変更は次回の接続から反映されます。以前はプロファイルの設定（**詳細設定** の中）でした。デバイスは、そのデバイス用に残したプロファイルの値を引き継ぎます（[コーデック](#codecs)を参照）。1.1 より前の v1 で保存したプロファイルには、そのとき全体で設定していた値が入ります。

**既定値の 1023 を推奨します。** Bluetooth のベースバンドパケット（3-DH5）1 つに収まる大きさです。大きくしても削減できるオーバーヘッドは 1〜2% 程度で、パケットが失われたときに失われる音声が長くなります。679 は 2-DH5 パケット 1 つ分で、LDAC が受け付ける最小値です。

## 送信ストリームの検証（a2dpwb_decode） {#verify-stream}

多くのヘッドホンは、使用中のコーデックを表示できません。**診断 > HCI キャプチャを開始** / **HCI キャプチャを停止** で、HCI パケットログ（設定フォルダーの `hci_<日付>_<時刻>.pklg`）を記録できます。コーデックの交渉内容と送信したすべてのメディアパケットが記録されます。LDAC 990 kbps では 1 時間あたり約 0.5 GB 増えるため、必要な間だけ記録してください。CLI モードでは `--hci-capture <file.pklg>` で実行全体を記録します。

キャプチャは接続前でもストリーミング中でも開始できます。接続中に開始した場合は、A2DPWB が記憶していた接続確立時のパケット（L2CAP チャネルの確立と、コーデック交渉を含む AVDTP シグナリング）を先に書き込むので、途中からでも解析できます。記録中と停止後は、診断にファイルのパスが表示されます。

キャプチャは Wireshark で開けるほか、開発者向けツール `a2dpwb_decode`（ソースからビルド。[ビルド](../building)を参照）で検証できます。

```
a2dpwb_decode "%APPDATA%\A2DPWB\hci_20260925_120000.pklg" -o C:\temp\check
```

このツールは AVDTP シグナリング（SET_CONFIGURATION / RECONFIGURE と、ヘッドホンがそれを受け入れたか）を追跡し、A2DPWB が送信したメディアパケットを取り出して、交渉した設定と照合します。

| コーデック | 検証内容 | 出力 |
|:-----------|:---------|:-----|
| SBC・AAC・aptX・aptX HD・aptX LL | リファレンスデコーダーで全体をデコード。フレームのパラメーターと設定の一致、メディアペイロードヘッダーのフレーム数 | 試聴用の `<prefix>.<n>.<codec>.wav` |
| LDAC | フレームヘッダーのみ（同期ワード、サンプルレート、チャンネルモード、フレーム長）、フレーム数、ビットレート。オープンソースの LDAC デコーダーは存在しません | レポートのみ |

各ストリームについて、RTP シーケンス番号の欠落、RTP タイムスタンプの進み方、ビットレート、Bluetooth コントローラーが送信完了を報告した ACL パケット数も表示します。最終行は `RESULT: OK` か `RESULT: PROBLEMS FOUND` です（終了コード 0 / 1）。

{: .note }
これで分かるのは、A2DPWB が何を送信したかと、その内容が交渉したコーデックとして正しいかです。受信側は交渉したコーデックでしかデコードできないため、ヘッドホンから正しく音が出ていて、かつレポートに問題がなければ、そのコーデックが実際に使われている強い根拠になります。

## 通信品質と AFH {#link-quality}

**診断 > 通信品質** には、ストリーミング中に A2DPWB が送信している内容を表示します: 実効ビットレート、送信パケット数、送信前に破棄したパケット（送信キューがあふれた = 電波が追いつかない）、音声取り込みの欠落、送信キュー、無線時間の使用率、そして **電波の強さ**: 接続の RSSI（コントローラーの適正な受信範囲との差。0 なら適正、マイナスは弱すぎ。絶対値ではありません）と、79 ある Bluetooth チャネルのうちホッピングに使っている数（AFH）。ホームとトレイのフライアウトでは、これを 良好 / やや不安定 / 不安定 にまとめて表示します。

Bluetooth は混んだチャネルを自分で避けます（AFH）が、Wi-Fi のことはエラーから学ぶしかありません。A2DPWB は、避けるべきチャネルをコントローラーにも伝えます（AFH ホストチャネル分類）。すべての接続に適用されます:

| AFH | |
|:--|:--|
| 自動（既定） | この PC が接続している 2.4 GHz の Wi-Fi のチャネルだけ（接続中は 30 秒ごとに確認し直します）。2.4 GHz の Wi-Fi につながっていないとき（未接続、5 GHz、有線）は何も伝えません。読むのはチャネル番号だけで、位置情報の許可は要りません。1〜14 番の 6 GHz のチャネルは 2.4 GHz として扱います |
| オフ | 伝えない（コントローラーに任せる） |
| 手動（例: `6,11`） | 指定した Wi-Fi チャネル（1〜14） |

自動では、聞こえるだけの Wi-Fi（近所のアクセスポイントなど）はコントローラー自身の AFH に任せます。混んだチャネルでも避けるとホッピングの幅が 22 MHz 減り、かえって通信が悪くなることがあるためです。それでも避けたいチャネルは手動で指定してください。

Bluetooth のチャネルは常に 20 以上残します。設定は **アダプタ** 画面、`settings.json`（設定フォルダ）の `"afh"`、CLI モードの `--afh` で行います。避けている Wi-Fi チャネルは電波の行に表示されます。効果は環境次第なので、対向受信テストで測って確かめてください。

## 対向受信テスト（tools/linux_sink） {#receiver}

通信品質に表示されるのは A2DPWB が送信した内容です。実際に何が届いたかを見るには、Linux の 2 台目の PC で `tools/linux_sink/a2dpwb_sink.py` を起動します。その PC の普通の Bluetooth アダプター（内蔵で可）を直接（Bumble、HCI ユーザーチャネル）A2DP シンクとして動かし、LDAC を含む全コーデックで届いたメディアパケットをすべて測定して、統計をネットワーク経由で提供します。

`tools/linux_sink` フォルダを Linux PC にコピーして（フォルダだけで動きます）、次を実行します:

```bash
sh setup.sh      # 初回のみ: デコーダーライブラリと Python 環境（Ubuntu / Debian、Python 3.11 以上）
sudo sh run.sh   # 受信側を起動（Bluetooth アダプターを使うため root）
```

Windows の PC では A2DPWB を終了して（トレイ > **終了**）、次を実行します:

```bash
a2dpwb-core.exe --cli --remote-sink auto -c ldac --test-tone
```

`--remote-sink auto` はローカルネットワークから受信側を見つけ、`-d` で別のデバイスを指定しなければ受信側の Bluetooth アダプターへ送信し、受信側の統計を 5 秒ごとと終了時に表示します: ビットレート、欠落・遅延パケット（RTP シーケンス番号）、ジッタと間隔、模擬した再生バッファの音切れ・音飛び、ストリーム／デコードのエラー、受信側の RSSI（適正な受信範囲との差。0 なら適正、マイナスは弱すぎ）。`--test-tone` を付けなければシステムの音を送ります。`--remote-sink <host[:port]>` で、探さずに受信側を指定できます。

{: .note }
同じテストはウィンドウでもできます。**設定 > 開発者モード** をオンにして **開発者 > 対向受信テスト** を開き、受信機を見つけて（またはアドレスを入れて）、コーデックと音源（テストトーンかシステム音声）を選んで送信します。手順ごとの確認と、送った内容と受信機が数えた内容の比較が表示されます。A2DPWB を終了する必要はありません。

パケット数は送信側・受信側ともストリームの最初のパケットから数えるので、送信数と受信数を比べられ、通常は一致します。Bluetooth は届かなかった無線パケットをコントローラーの中で再送し、A2DPWB はリンクが続く限りパケットをあきらめないため、電波が悪いときは欠落ではなく受信側の間隔・ジッタ・音切れとして現れます。電波が追いつかないときは、送信側で送信前に破棄されます。再送の回数は送信側・受信側のどちらからも取得できません。

ツールの実行中、受信側 PC の Bluetooth スタックはそのアダプターを使えません。検出は UDP ブロードキャスト（ポート 51201）なので、2 台は同じネットワークセグメントにある必要があります（そうでなければアドレスを指定します）。オプションと統計のプロトコルは `tools/linux_sink/README.md` を参照してください。

## LE Audio（実験的） {#le-audio}

A2DPWB は LE Audio のヘッドホンやイヤホンにも送れます（BAP ユニキャストで LC3 を接続型アイソクロナスストリームに乗せる）。ヘッドセットの音量（VCP）、メディアボタン（MCP）、左右のイヤホンの組（CSIP）、ゲーミングヘッドセット向けの低遅延モード（GMAP）にも対応します。この機能は**実験的**で、デバイスごとに選びます。デバイスの LE Audio の項目だけが使います。確かめたのは Bluetooth のエミュレータだけで、**実機の LE Audio ヘッドホンではまだ試していません**。お使いの機器では動かないこともあるので、普段の視聴には従来の A2DP を使ってください。

必要なもの:

- **Bluetooth 5.2 以降でアイソクロナスチャネル（ISO）に対応した** USB Bluetooth アダプター（A2DP と同じく WinUSB を割り当てる）。ISO に対応していないアダプターでは「adapter does not support LE Audio (no ISO buffers)」で止まります。
- LE Audio（LC3）に対応したヘッドホンやイヤホン。機種によっては、先に専用アプリで LE Audio を有効にする必要があります。

使い方:

1. ヘッドホンをペアリングモードにして、**オーディオデバイス** でデバイスをスキャンします。LE Audio のデバイスには **LE Audio**、左右一組のイヤホンには **LE Audio セット** の印が付きます（どちらか片方を選べば、もう片方は A2DPWB が探します）。A2DP にも対応したヘッドホンは、種類ごとに 2 回表示されます。
2. **コーデック** 画面で、LE Audio の項目の LC3 のカードを選びます。コーデックや品質は選べません（ヘッドホンが受け付ける一番よい LC3 の設定を A2DPWB が選びます）。取り込みはシステムループバックと仮想デバイスだけです。
3. その下の **ゲーミングヘッドセット向け低遅延（GMAP、実験的）** は既定でオンです。GMAP のゲーム用の役割に対応したヘッドセットでは短い LC3 フレームを使い、それ以外のヘッドセットではどちらでも通常の設定になります。

設定画面に LE Audio のスイッチはありません。万一 LE 側がアダプターの動作を妨げるときは、`settings.json`（**設定 > 設定フォルダ**）の `"le_audio_experimental": false` で LE をまとめて止められます。

CLI モードでは `--le-audio -d <アドレス>` で LE Audio のデバイスに送ります。`--le-device <アドレス>` でグループのもう 1 台（もう片方のイヤホン）を加え、`--le-scan` で近くの LE Audio デバイスを一覧し、`--le-low-latency` / `--le-preset <名前>` で設定を選びます（LE のオプションの一覧は `a2dpwb-core.exe --cli -h`）。

## 更新 {#updates}

A2DPWB は GitHub Releases を 1 日に 1 回まで確認します（**設定 > 起動時にアップデートを確認**。**アップデート確認にプレリリースを含める** でベータ版も通知）。新しいバージョンがあれば、新しい点を数行にまとめたダイアログを表示します（全文はリンク先）。**今すぐ更新**（ポータブル版は **ダウンロードページを開く**）と **後で** があり、**後で** を選ぶと次のバージョンまでは設定にだけ表示します。設定にも表示されます。

- **インストール版**: **今すぐ更新** で署名付きの更新をダウンロードします。オーディオデバイスの接続中は待ち、切断したときにインストールするので、更新で音が切れることはありません。A2DPWB はいったん終了し、新しいバージョンをインストールして、自動で再び起動します。
- **ポータブル版**（または更新の署名がないビルド）: **ダウンロードページを開く** でリリースのページを開きます。

## トラブルシューティング

### コアが動いていないと表示される

ウィンドウは隣にある `a2dpwb-core.exe` を自分で起動します。「A2DP Windows Bridge のコアが動いていません」は起動できなかったという意味です。A2DPWB をインストールし直してください（ポータブル版なら zip を展開し直します）。「コアのバージョンが合いません」は、2 つのプログラムのバージョンが違うという意味です。両方を同じバージョンにしてください（最新のリリースをインストールすればそうなります）。

### ドライバーの割り当てや復元に失敗する

- 「管理者の確認が拒否されたため、ドライバは変更していません」: もう一度ボタンを押し、確認を許可してください。
- 「ドライバを変更できませんでした」: 詳しくは **診断** のログを見てください。
- 「元のドライバには戻りませんでした」: Zadig で設定したアダプターでは、Windows がまた Zadig の WinUSB ドライバーパッケージを選ぶことがあります。デバイスマネージャーでそのドライバーパッケージを削除し（アダプター > デバイスのアンインストール、「このデバイスのドライバーを削除しようとしました」にチェック）、アダプターを抜いて挿し直してください。

### Bluetooth アダプターが応答しない {#adapter-no-answer}

開いたアダプターから何も返ってこない（HCI Reset に応答しない）場合、A2DPWB は 5 秒で見切り、もう一度だけ開き直します。それでも応答しなければ「Bluetooth アダプターが応答しません」と表示します。アダプターを抜いて挿し直してから、もう一度お試しください（または **Bluetooth を再起動**）。A2DPWB の再起動は不要です。開始に失敗してもアダプターは解放され、次の開始で初期化し直します。

アダプターが固まらないよう、A2DPWB は開くときに USB パイプをリセットし、閉じるときに HCI Reset を送ります。

### アップデート後にペアリングがうまくいかない

A2DPWB は SSP（Just Works）と **General Bonding** でペアリングし、リンクキーを保存するため、次回以降はペアリングし直さずに再接続できます（v2 は v1 のリンクキーを読みます）。以前のバージョンの A2DPWB でペアリングしたヘッドホンにつながらなくなった場合は、ヘッドホン側で A2DPWB のペアリング情報を削除し（ペアリング履歴の消去方法はヘッドホンの説明書を参照）、改めてペアリングしてください。

### 接続がタイムアウトする

A2DPWB は SDP レコード（A2DP Source、AVRCP Controller / Target）を登録し、ヘッドホンがオーディオソースとして認識できるようにしています。接続がタイムアウトした場合は中途半端な接続が破棄されるため、A2DPWB を再起動せずにそのまま再試行できます。ヘッドホンの電源が入っていること、通信範囲内にあること、他の機器に接続されていないことを確認してください。

接続が確立した後に通信が届かなかった場合と、ヘッドホンが応答しなかった場合は、自動で再試行します（最大 3 回）。ヘッドホンがペアリング情報を失っている場合（リセットや別の PC とのペアリング）は、保存したキーを破棄して 1 回だけペアリングし直します。失敗したときは、何が起きたかを表示します:

| メッセージ | 意味 |
|:--|:--|
| デバイスが応答しません | 電源オフ、範囲外、または接続できない状態（新しいデバイスはペアリングモードに） |
| 接続は確立しましたが、その後の通信が届きませんでした | 電波状態: もう一度試すか、アダプターとデバイスの位置を見直す |
| デバイスは応答しましたが、デバイス側から接続を切られました | 今は接続を受け付けない状態: 電源を切る途中、充電中、別の機器と接続中など |
| 認証に失敗しました（ペアリングし直しても失敗） | デバイスをペアリングモードにするか、デバイス側のペアリング情報を削除して再試行 |

ヘッドホンへの**最初の接続**にはペアリングモードが必要です。2 回目からは保存したリンクキーで再接続します。ペアリングモードにしても失敗するときは、ヘッドホンがスマホや別の PC にまだ接続されている（LE Audio 経由も含む）ことがあります。そちらの接続を切り、ヘッドホンのアプリに LE Audio の設定があればオフにしてから、ペアリングモードにしてもう一度接続してください。ログには `signaling connection failed (0x66)`（セキュリティ上の拒否: この PC の Windows Bluetooth などとの以前のペアリングのキーをヘッドホンが保持している）や `(0x67)`（リソース不足による拒否: 別の機器が使用中）が出ます。

切れた接続は自動で再接続します（最大 10 回）。配信中に PC がスリープに入ったときは、復帰した後に再接続します。この再接続は回数に数えません。
