# 音切れと接続の問題
{: .no_toc }

音が途切れる、音飛びする、止まる。接続が確立しない。ビットレートが想定より低い。このページでは、そうした報告が結局何だったのかをまとめ、報告する前によくある原因を確かめられるようにし、どれにも当たらないときに何を送ればよいかを説明します。

## まず確かめること {#checklist}

Bluetooth は 2.4 GHz 帯を、Wi-Fi、ワイヤレスのマウスやキーボード、ヘッドセットのドングル、そして部屋にあるほかのすべての Bluetooth 機器と共有しています。USB アダプターのアンテナは小さく、イヤホンのアンテナはさらに小さいうえ、イヤホンと PC の間にはあなたの頭があります。これまでの「接続が悪い」という報告の多くは、次のどれかが原因でした。どれも 1 分で試せます。不具合報告のフォームにはそれぞれのチェック欄があるので、試したものにチェックを入れてください。

{: .note }
一度に 1 つずつ変えて、その間に数分間聞いてみてください。音切れが止まれば、それが原因です。

### 1. この PC のほかの Bluetooth アダプターを無効にする

Windows 自身の Bluetooth（内蔵アダプター）は、A2DPWB がその隣の USB アダプターで配信している間も送信を続けていて、両者は同じ帯域を、多くの場合は同じアンテナの位置も共有しています。PC 上のヘッドホンのアプリが接続するのもこの内蔵アダプターで、ヘッドホンに 2 本目のリンクができます（次の項目を参照）。A2DPWB を使う間、少なくともテストの間は、デバイスマネージャーで内蔵アダプターを無効にしてください。A2DPWB は、ほかに有効なアダプターを見つけるとホームに通知を表示します。

2 つ目の有効なアダプターは、長く使っているテスターが接続の不安定さとコーデック切り替えの原因として挙げた 2 つのうちの 1 つです。

### 2. ヘッドホンの接続を 1 本だけにする

デュアル接続（マルチポイント）では、ヘッドホンがスマホと PC に同時につながったままになります。接続はどれも無線時間を消費し、ヘッドホンによっては提示するコーデックが減る、ハンズフリーのリンクを拒否する（バッテリー残量が出ない）、もう一方の機器のためにコーデックのエンドポイントを確保したままにする、といったことも起きます。ヘッドホンの純正アプリも同じです: バッテリーやイコライザーにしか使っていなくても、スマホかこの PC の Bluetooth から独自のリンクを開いたままにします。

テストでは、ヘッドホンのアプリでデュアル接続をオフにし、スマホの Bluetooth をオフにし、スマホと PC の純正アプリを終了してから、A2DPWB からもう一度接続してください。

デュアル接続は、そのテスターが挙げたもう 1 つの原因です。純正アプリを切断すると、コーデックの切り替えはずっとスムーズになりました。ヘッドホンが LE Audio をオンにしたスマホにまだつながっていたために最初の接続が拒否された例や、スマホやアプリが関わっている間は A2DPWB に提示するコーデックが減ったりビットレートが低くなったりしたイヤホンがいくつかありました。Sony の LDAC は、ヘッドホンのマルチポイントがオンの間はオフになります。

### 3. アダプターの位置を変える

- **USB 2.0 ポート**か、短い USB 延長ケーブルを使います。USB 3 のポートとケーブルは 2.4 GHz 帯、まさにアダプターのある場所にノイズを出します。
- **ほかの無線受信機から離します**: ゲーミングマウスやキーボードのドングル、ワイヤレスヘッドセットのドングル、Wi-Fi のアンテナ。隣のポートの受信機は、まさにこのパターンのよくある原因です。
- **ヘッドホンから見える場所に置きます**。机の下の PC では、あなたと机が間に入って信号が大きく失われます。机の上まで届く USB 延長ケーブルが何よりも効きます。

AFH を導く Wi-Fi アダプターのない PC で、アダプターの隣にゲーミングマウスの受信機があったケースでは、リンクは約 750 kbps しか運べず、アダプターは 79 チャネルのうち最大 46 を不良と判定しました。アダプターから 1 m のイヤホンでも電波は弱いと表示され、ビットレートの上限付近では数分おきに無音になるのに十分でした。

### 4. 2.4 GHz の Wi-Fi をリンクから遠ざける

この PC、できればスマホや近くのほかの機器も、5 GHz か 6 GHz の Wi-Fi に移します。2.4 GHz をオンのままにする必要があるなら、A2DPWB はこの PC が接続しているチャネルを避けるようアダプターに伝えます（AFH、自動）。PC に Wi-Fi アダプターがない、有線でつないでいる、ルーターの 2.4 GHz ネットワークとは別の帯域につないでいる場合は、Wi-Fi が見えません。そのときはルーターのチャネルを調べ（管理ページか、スマホの Wi-Fi アナライザーアプリ）、チャネルが変わるならそこで固定して、**アダプタ > Wi-Fi チャネルの回避 > 手動** に `6` や `11` のように入力してください。[通信品質と AFH](usage#link-quality)を参照してください。

LDAC 990 kbps は、混んだ 2.4 GHz ネットワークでは 5 分間に約 1,700 パケットを失いましたが、ルーターを 1 つのチャネルに固定して AFH を手動でそのチャネルにすると、15 分間で 33 パケットでした。

### 5. リンクに余裕を持たせる

Bluetooth のリンクは、条件が完璧でも 1 Mbps を少し超える程度しか運べません。LDAC 990 kbps、LHDC V5 の 900 と 1000 kbps、ビットプールの高い SBC XQ では、再送のための余地がほとんど残りません。完全ワイヤレスのイヤホンは音声を片方からもう片方へ中継し、これも無線時間を消費するので、きれいなリンクでも 900 kbps 以上は厳しいです。

- **ABR**（適応ビットレート。LDAC、LHDC V5、aptX Adaptive、SBC は適応ビットプール）か、1 段下げたもの: LDAC 660、LHDC V5 500、SBC XQ ビットプール 29〜36 を試します。
- **SBC か AAC** でも音切れが続くか確かめます。続くなら、ビットレートが原因ではありません。
- ヘッドホン側の確認として: スマホとペアリングし、そこで同じコーデックとビットレートにして、同じ場所で聞きます。そこでも音切れするなら、限界はヘッドホン側にあります。

750 kbps しか運べなかったリンクでは、500 kbps を超えるとすべて途切れ、ABR では欠落はゼロでした。SBC XQ はビットプール 36 を超えると、SBC の能力では 53 まで許していた低価格のイヤホンで無音になりました。同じイヤホンで LHDC V5 はランダムに途切れ、LDAC は安定していました。きれいなリンクなら運べます: ノート PC の内蔵アダプターは LDAC 990 kbps を 5 分間、パケットの欠落 0 で配信しました。

### 6. A2DPWB を更新する

電波のように聞こえた音飛びのいくつかはアプリが原因でした。2.0.1 は仮想ケーブルが音声を遅れて渡すと実時間より速く音声を送り、ヘッドホンには 1 秒の音と 1 秒の無音として聞こえました。切断 > 接続 の後のストリームは、アプリを再起動するまで音飛びしました。古くなった Bluetooth スタックは、スリープ、長時間のセッション、何度もの再起動の後に接続を拒否しました。いずれも現在のリリースで修正されています（[更新](usage#updates)）。更新して問題がなくなれば、報告は不要です。

## 通信品質の読み方 {#link-quality}

**診断 > 通信品質**（とホームのグラフ）は、電波、PC、アプリのどれが原因かを見分けます。問題が起きている間にスクリーンショットを撮り、報告に添えてください。

| 表示 | 意味 | 原因の所在 |
|:--|:--|:--|
| **電波（理想との差）** が 0 を大きく下回る（約 -25 dB 以下） | ヘッドホンの信号が、アダプターの適正な範囲をはるかに下回る強さで届いている。絶対値ではなく、0 が理想、-30 はその 30 dB 下。-30 でも再生はできるが、余裕はない | 電波: 距離、頭や体、アダプターの位置 |
| **送信キュー** がいっぱい、**送信前に破棄したパケット** が増える、ビットレートがコーデックの値を下回る | パケットが電波を待ちすぎた。リンクは今このビットレートを運べない | 電波か干渉、またはビットレートが高すぎる |
| **周波数ホッピング（AFH）** が飛び回る、またはパケットが失われているのに 79 のまま | アダプターがエラーの出たチャネルを不良と判定している。79 では区別をあきらめている | 干渉: Wi-Fi、ほかの受信機、2 つ目の Bluetooth アダプター |
| **音声取り込みの欠落** が増える、ホームに **PC処理落ち** | PC が音声を間に合うように渡さなかった | PC: 負荷、キャプチャデバイス、仮想ケーブル |
| すべて平らで空なのに、無音や音飛び | リンクは正常で、PC 側でも何も欠落していない | アプリかヘッドホンのデコーダー: 診断パッケージを付けて報告してください |

受信側は PC から見えません。実際に何が届いたかを測るには、[対向受信テスト](usage#receiver)で Linux PC をヘッドホンの代わりにします。

## ヘッドホンが決めること {#headphones}

「400 kbps しか出ない」「LDAC がない」という報告の一部は、リンクとはまったく関係がありません。ヘッドホンが受け付けるコーデックとビットレートを A2DPWB に伝え、A2DPWB は Android と同じようにそれに従います。ログの `remote supports ...` の行に、ヘッドホンが提示したものが出ます。

- **Huawei FreeBuds** は、AI Life アプリで「音質優先」にしてマルチ接続をオフにした後でだけ、PC に LDAC を提示します。それ以外では SBC と AAC だけを並べます。2.0.2 からは、自動選択がオフで LDAC を選んだとき、A2DPWB がそのモードを自分で要求します。
- **LHDC V5 のヘッドホン** は最大ビットレートを通知します。ある機種はアプリの 96 kHz モードでは 400 kbps、192 kHz モードでは 1000 kbps を通知しました。OPPO Enco Free4 と Enco X4 は、アプリの設定にかかわらず PC には 400 kbps と 48 kHz を通知します。2.0.2 は ABR オフで LHDC V5 を配信するときに OPPO 独自のプロトコルでハイレゾを要求し、そのために一度だけ接続し直します。実機のイヤホンではまだ確認していません。
- **ABR** は、Android と同じく LHDC V5 を 400 kbps 以下に保ちます。
- ヘッドホンが**別の機器のために確保している**コーデックは、その機器が接続している間は出てきません（[ヘッドホンが別の機器とも接続中でコーデックが出てこない](usage#sep-in-use)）。

提示されているものの確認方法: [ヘッドホンが提供するコーデックの確認方法](usage#codec-fallback)。

## 接続に失敗する {#connecting}

ホームのエラーに何が起きたかが出ます。各メッセージは[接続がタイムアウトする](usage#connection-timeouts)の表で説明しています。電波に関わるケース:

- **デバイスが応答しません**（Page Timeout）: 電源が切れている、範囲外、最初の接続なのにペアリングモードでない、またはアダプターがまだ ROM のファームウェアで動いている。ファームウェアのない Realtek アダプターは、検索で何も見つからず接続のたびにタイムアウトするか、開けても配信が始まりません。ファームウェアのファイルが、保存した Web ページだったこともあります。ファームウェアが読み込まれているかはアダプタ画面に表示されます。
- **接続は確立しましたが、その後の通信が届きませんでした**: 電波の状態か、ヘッドホンが別の機器で手一杯です。もう一度試し、アダプターの位置を変えてください。
- **認証に失敗しました**、またはログに `signaling connection failed (0x66)`: ヘッドホンが以前のペアリングのキー、たいていはこの PC 自身の Windows Bluetooth のキーを保持しています。`(0x67)`: 別の機器、たとえば LE Audio をオンにしたスマホで手一杯です。ほかの機器を切断し、ヘッドホンのアプリで LE Audio をオフにして、ペアリングモードにして一度接続してください。以降の接続は保存したキーを使います。
- 切断の後、ヘッドホンが**スマホに接続できない**: 2.0.2 は切断でリンクを手放します。ヘッドホンの電源を切って入れ直すことで PC とスマホを行き来させているなら、**自動で再接続する** をオフにしてください。

## 報告は結局何だったのか {#reports}

無線側に関わるこれまでのすべての報告を、最終的な原因で分けたものです。

| 原因 | 報告 | 例 |
|:--|:--|:--|
| **環境**: 電波、置き場所、別の機器 | 約 3 分の 1 | 同じチャネルの 2.4 GHz Wi-Fi、アダプターの隣のゲーミングマウスの受信機、2 つ目の有効な Bluetooth アダプター、デュアル接続と起動中の純正アプリ、完全ワイヤレスイヤホンでの余裕のないビットレート、小さなイヤホンの弱い電波、保存した Web ページだったファームウェアファイル |
| **ヘッドホン**: PC に提示するもの | 約 4 分の 1 | Huawei の音質モードにした後でだけ出る LDAC、ヘッドホン自身のモードで 400 kbps に制限された LHDC V5、OPPO のプロトコルで設定するハイレゾ、スマホのために確保されたコーデック |
| **アプリ**: A2DPWB の不具合、すべて修正済み | 半分弱 | 仮想ケーブルで実時間より速く送られた音声、切断 > 接続 の後の音飛び、スリープや何度もの再起動の後の古くなった Bluetooth スタック、切断後も保たれたリンク、先に接続してきたヘッドホンを誤ったキーと取り違えた、LDAC を隠したコーデックのキャッシュ、認識されないアダプター（チップ、USB クラス、まだ有効になっていないドライバーの割り当て） |

目立つ点:

- **音飛びと音切れはアプリと環境でほぼ半々**でした（アプリ側は 2.0.1 と 2.0.2 の最初のベータのタイミングの不具合）。測定できた 2 件の干渉のケースは同じ絵を示します: 送信ビットレートが 550〜800 kbps に落ち、送信キューがいっぱいになり、アダプターのチャネルマップが 79 分の 79 になります。
- **接続の問題はほとんどアプリ**で、そのほぼすべてが 1 つの経路、電源を入れたヘッドホンが自分から接続を開く経路で起きていました。Bluetooth エミュレーターではこの経路を動かせないので、これらの修正はユーザーのログに頼っています。
- **「コーデックがない」「ビットレートが上がらない」はヘッドホン**が PC に何を提示するか決めていたもので、たいていは純正アプリに左右されていました。
- **電波のように見えて違った**問題もあります: ある機種での AAC の無音（フレーム形式）、ヘッドホンの電源が切れた後も仮想ケーブルのままだった Windows の出力、コーデック変更で接続し直す間に数秒スピーカーから出る音、有線ヘッドホンからも音が出る（システムループバックの仕組み）。

## 報告 {#reporting}

上の確認で見つからなければ、[不具合報告](https://github.com/SeiyaFunaokaJP/A2DP-Windows-Bridge/issues/new?template=bug_report.yml)を開き、試したものにチェックを入れてください。無線の報告が早く片付くもの:

1. **診断 > 問題を報告** で **詳細ログ** を **詳細（debug）** にしてから、問題を再現します。
2. **診断パッケージ**（**HCI キャプチャを含める** をオンにして **診断パッケージ > 保存…**、次に **GitHub で報告**）。ストリームの状態の行（送信キュー、破棄したパケット、電波、AFH のチャネルの推移）と、失敗した接続の HCI キャプチャが入っていて、パケットがどこで止まったかが分かります。
3. 問題が起きている間の **通信品質のスクリーンショット**。
4. **SBC か AAC** でも、**低いビットレート** でも起きるか。
5. フォームのデュアル接続、別の Bluetooth アダプター、Wi-Fi の質問への回答。
